## 1. 提案の要旨

「おすすめ(推し度)」の算出規則を知識ベース正本へ `oshi_v0.json` として収録する。
由来の異なる独立レンズ——本質(純占術: 馬×騎手の調和+馬×レース日の流れ)と調律(戦績の波形)——が
同じ方向を向く「収束」を核とする最終評価であり、勝率・的中率・レース結果の予測を表すものではない。

**設計上の最重要点: オッズ(集合意識)をスコアに使用しない。**
人気ベースラインとの比較による検証可能性を保つため(synchro提案書§4-4の警告と同根。
その警告は2026-08-02のrun6——熱量v0がギャップ点で素の収束度に敗北——で実証された)。
集合意識は「隠れ推し」の物語チップとしてのみ参照する。

## 3. 検証実績(この提案の根拠。run2〜run6、2026-07〜2026-08-02)

- 収束度の累積(run2-6): 人気帯内の相対比較で 4-6人気 **+6.6pt** / 7人気以下 **+2.8pt** / 1-3人気 **−12.5pt**
- run6(2026-08-02、SED260802・459/464頭照合): 同一382頭の直接比較で、
  素の収束度のみ 上位20複勝率 **35.0%** / 上位50 **40.0%**。
  オッズ由来のギャップ点を混ぜた熱量v0(10.0%/20.0%)に対して明確に優位
- run5: 「1番人気を買うだけでは概算回収85%止まり」— ベースライン比較の物差しとして機能

## 4. 正本側で確定・検討してほしい事項

1. 1-3人気で**−12.5pt**という符号反転の扱い(人気帯で規則を分けるか、適用範囲を明示するか)
2. adjustersレジストリ(枠順・トラックバイアス等、現在weight=0)の組込み判定基準の明文化
   (policy: verification_required_before_weighting は収録済み。判定の閾値が未定義)
3. verification_plan.json への正式登録(推し帯別の勝率・複勝率を人気帯ベースラインと比較する設計。
   oshi_v0.meta.verification_plan に記載済みの方式を正本の事前登録へ昇格させる)
4. 地運・天運(racecourse_geography / sizhu_day_pillar 由来)を将来adjustersへ入れる場合の検証設計
